Platform Architecture — AI inside, not LLM-then-trades

BTC perpetual futures primary (5m–1h horizon). NIFTY futures second. NIFTY options deferred (contract-surface complexity). Research/execution platform with six systems.

6 layers (the systems you described)

Market Sources input

BTC venue WebSocket/REST; NIFTY broker (Kite / Upstox); macro/news feed.

Market State state

Normalized common schema: price / book / vol / OI / funding / regime / liquidity. Redis hot.

Quant Engine model

LightGBM/XGBoost baselines + PyTorch where justified. Outputs probs per horizon (5m–1h).

Frontier Brain reason

Hypothesis generation + strategy design + regime analysis. Produces policy candidates, never direct orders.

Policy Engine control

Strategy version / conditions / thresholds / allowed actions. Converts brain output to executable policy.

Jev decision

TypeSafe API: yes/no, choice, evaluation, ratings. Answers multiple bounded questions per state.

Risk Kernel gate (hard)

Position / loss / exposure / spread / liquidity / kill-switch / stale-data limits. Non-AI; cannot be overridden.

Execution act

Deterministic sizing + market/limit/stop + fill tracking. Shadow + live paths.

Observability feedback

PnL attribution / calibration / strategy degradation. Replay by timestamp. Feeds research loop + adversarial model.

Storage / Bus infra

Redis (hot) · ClickHouse (ticks) · Parquet archive · Postgres (metadata) · NATS / Redpanda.

Orientation decision (from your spec, not my inference)

BTC perpetual futures — first market (5m–1h)

Continuous 24/7 market = cleanest lab for slow strategic reasoning + fast repeated evaluation. Frontier can reassess every 15–60m; Jev operates continuously. No expiry/strike/Greeks/IV/louidity-spread/commercial-constraints noise.

NIFTY options — deferred, not rejected

Built into platform day one. Not started because the contract state is substantially richer: NSE currently has four weekly NIFTY expiries plus monthly/quarterly/longer-dated contracts; weekly and monthly NIFTY options expire Tuesday. Direction + magnitude + timing + IV + skew + expiry + strike selection + theta + gamma + spread/Greeks/liquidity = far more state than BTC perp. ([NSE India][1])

Also: Indian retail-algo framework (SEBI, applicable to all brokers from Apr 1 2026) is part of engineering requirements, not an afterthought. ([SEBI][11])

Why not NIFTY futures as first? It's second.

NIFTY futures add only the daily market window (NSE 09:15–15:40 IST + pre-open 09:00) — manageable, but less continuous opportunity for the architecture to operate. Included from the start as a parallel instrument; BTC perp remains the primary testbed.

The interface separation (what makes this a platform, not an LLM that trades)

FRONTIER MODEL (slow, periodic)
  → strategy / policy CANDIDATE (not an order)
  → POLICY ENGINE (version / conditions / thresholds / allowed actions)
  → JEV (fast, bounded, TypeSafe: yes/no/choice/evaluation/ratings)
  → RISK KERNEL (hard non-AI rules — cannot be overridden by any model)
  → EXECUTION ENGINE (deterministic sizing + orders + fills)
  → MARKET (fills / positions feed back to market state)
  → OBSERVABILITY (PnL attribution / calibration / degradation / replay)
  → RESEARCH / FRONTIER (new hypotheses, adversarial kill-strategy, shadow trader)

Meanwhile, Jev answers continuously — never trying to "reason" the strategy, only evaluate whether current state satisfies the policy conditions.

Learning loop (not continuous live modification by the model)

Strict loop — live data does NOT feed directly back into live strategy

Live → Data → Attribution → Research → Frontier (hypotheses) → Strategy v2 → Backtest → Walk-forward → Paper → Shadow → Live. Shadow + adversarial process runs alongside. MLflow tracks versions so you can say exactly which data/features/parameters/training/backtest/deployment produced each strategy.

Adversarial + shadow (your idea, made explicit)

Shadow trader audit

Every live decision → actual trade + hypothetical (shadow) trade. Discover whether Jev / frontend / quant actually contribute vs baseline / randomized.

Adversarial strategist kill

Second frontier process: "Why shouldn't we trade?" Tests regime change, cost erosion, overfit, signal degradation — before the live strategy convinces itself.

Replay audit

Replay market-state at 10:37:21 Mar 18 → reproduce decision. More valuable than a fancy dashboard.

Deployment (v1 — keep it small)

DEV: laptop (Python / Jupyter / Polars / VectorBT / PyTorch / LightGBM / MLflow / Docker)
PROD (v1): one Linux VPS — 8 vCPU / 16–32 GB RAM / NVMe / Ubuntu / Docker Compose
Containers: market-feed · state-engine · feature-engine · quant-engine · jev-service · policy-engine · risk-engine · execution-engine · clickhouse · postgres · redis · nats · mlflow · monitoring · dashboard

No Kubernetes, no Kafka clusters, no GPUs, no co-location — architecture theatre is what this design avoids.
